## ADDED Requirements

### Requirement: 主题详情页展示可折叠主题头部

话题和数码详情页 MUST 在现有可折叠 AppBar 中展示主题图标、名称、简介和服务端实际返回的统计信息；缺失字段 MUST 被隐藏，不得展示 `null` 或虚构内容。

#### Scenario: 话题详情加载头部

- **WHEN** 话题布局接口返回 logo、intro 或统计字段
- **THEN** 页面在 Toolbar 下方展示对应信息，并保留原有服务端 Tab 和内容列表

#### Scenario: 统计字段缺失

- **WHEN** 布局接口未返回某一项统计信息
- **THEN** 该统计项隐藏，其他可用信息和内容列表仍正常显示

### Requirement: 用户可以从主题头部一步关注或取消关注

主题详情页 MUST 在头部提供“关注 / 已关注”直接操作。点击后 MUST 立即反映本地关注状态；服务端同步失败 MUST NOT 撤销本地状态或阻断页面浏览。

#### Scenario: 未登录用户关注主题

- **WHEN** 未登录用户点击“关注"
- **THEN** 本地关注记录被保存，按钮变为“已关注”，并提示关注成功

#### Scenario: 已登录用户取消关注

- **WHEN** 已登录用户点击“已关注”
- **THEN** 本地关注记录被删除，按钮变为“关注”，同时尽力同步服务端取消关注

### Requirement: 讨论 Tab 提供直接排序切换

当当前 Tab 标题为“讨论”时，页面 MUST 展示单选排序控件“默认 / 最新 / 热度”。排序控件 MUST 不依赖 Toolbar 溢出菜单。

#### Scenario: 切换到最新排序

- **WHEN** 用户点击“最新”
- **THEN** 页面清空旧列表、重置分页游标，并使用当前讨论 Tab URL 的 `listType=dateline_desc` 重新加载

#### Scenario: 切换到热度排序

- **WHEN** 用户点击“热度”
- **THEN** 页面清空旧列表、重置分页游标，并使用当前讨论 Tab URL 的 `listType=rank_score` 重新加载

#### Scenario: 切换回默认排序

- **WHEN** 用户点击“默认”
- **THEN** 页面移除排序覆盖并使用当前讨论 Tab 的原始 URL 重新加载

### Requirement: 排序切换不得混用分页结果

排序切换 MUST 重置 `page`、`lastItem` 和结束状态；新的排序请求完成前不得继续追加旧排序列表。

#### Scenario: 已加载多页后切换排序

- **WHEN** 用户已经加载多页内容并切换排序
- **THEN** 新列表从第一页开始，旧列表不会出现在新排序结果中

### Requirement: 现有详情页能力保持不变

主题页 MUST 保留服务端 Tab、动态内容列表、分页、黑名单过滤、发布入口和本地关注页跳转；应用页和用户页使用的共享菜单行为 MUST 不受影响。

#### Scenario: 主题页继续分页

- **WHEN** 用户滚动到讨论列表底部
- **THEN** 当前排序下继续使用原有分页机制加载下一页

#### Scenario: 其他详情页打开菜单

- **WHEN** 用户打开应用详情页或用户详情页的关注菜单
- **THEN** 原有菜单行为保持不变
