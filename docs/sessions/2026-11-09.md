# 2026-11-09 会话记录

## Goal

参考 `XiaoMengXinX/c001apk_next`，将 Coolapk API 请求身份切换为 iOS 客户端实现，以处理评论接口异常。

## Changes

- 新增 iOS 请求 Header、设备串与 Token 生成实现，并使用 `credentials.xml` 持久化匿名 UUID 和 iPhone 档案。
- API1/API2 拦截器改为 iOS 身份，继续保留匿名 SESSID 和可信 HTTPS Host 边界。
- 设置参数页切换为 iOS 身份档案编辑和派生 Header 查看；Coolapk 图片及 Coolapk 起始 WebView 请求使用 iOS User-Agent。
- 同步更新 API、架构、项目上下文、技术决策和待办文档。

## Problems

- 本轮未发现无法解决的实现阻塞。
- 上游实现包含登录与 CDID 行为；本项目维持匿名只读范围，没有移植这些能力。

## Decisions

- 评论列表和楼中楼继续使用现有 API2 路由及分页参数，只切换共享请求身份。
- 保留旧 Android Token 代码/凭证字段以避免顺手清理兼容数据；当前 API 拦截器不再使用它们。
- 真实设备及评论接口未验证，单独记录为待办 R-016。

## Next

- 在 Android 设备构建并发起评论列表、楼中楼请求，核对状态码、响应解析、分页展示及非可信 Host 凭证清理。
- 完成验收前不把 iOS 请求身份描述为已恢复线上评论接口。

## 后续修复：帖子图片预览缩放手势

### 发现

- 用户确认点击帖子图片后可以进入预览，问题是预览内无法放大或缩小。
- 本地 `MojitoView.dispatchTouchEvent()` 与参考仓库 `c001apk_next` 存在相同逻辑：在 `isMultiFinger` 且此前单指纵向位移非零时直接返回，吞掉缩放器需要的多指 `ACTION_MOVE`。
- `SketchContentLoaderImpl` 已启用 `SketchImageView.isZoomEnabled`；图片点击入口和预览启动链路不需要修改。

### 修改

- 移除多指移动事件的提前返回；多指期间仍跳过 Mojito 自身拖动处理，事件继续交给子图片缩放器。
- 撤回与“预览已打开但缩放无效”无关的图片下载器、图片客户端及 Sketch 预热改动。
- 同步更新图片架构说明、决策记录和 R-017 待办；评论区手工验证结论保持记录。
