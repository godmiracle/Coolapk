## Goal

参考 `XiaoMengXinX/c001apk_next`，将 Coolapk API 请求身份切换为 iOS 客户端实现，以处理评论接口异常。

## Changes

- 新增 iOS 请求 Header、设备串与 Token 生成实现，并使用 `credentials.xml` 持久化匿名 UUID 和 iPhone 档案。
- API1/API2 拦截器改为 iOS 身份，继续保留匿名 SESSID 和可信 HTTPS Host 边界。
- 设置参数页切换为 iOS 身份档案编辑和派生 Header 查看；Coolapk 图片及 Coolapk 起始 WebView 请求使用 iOS User-Agent。
- 同步更新 API、架构、项目上下文、技术决策和待办文档。

## Problems

- 本轮未发现无法解决的实现阻塞。
- 上游实现包含登录与 CDID 行为；本项目维持匿名只读范围，没有移植这些能力。

## Decisions

- 真实设备及评论接口未验证，单独记录为待办 R-016。

## 真机复测更正：图片加载失败时加载层拦截触摸

### 根因与修改

- 此前将 `MojitoView` 的多指早退判断作为缩放失败根因并不准确；OPPO PMX110 / Android 17 的真机诊断显示，图片请求失败后 `loadImageFail()` 让全屏 `loadingLayout` 保持可见。`DefaultPercentProgress.onFailed()` 隐藏了其中的进度子视图，但父层仍有全屏点击监听，实际触发关闭预览，图片视图收不到触摸。
- 修复在 `loadImageFail()` 处理后禁用 `loadingLayout` 点击；下次加载开始或收到进度时恢复点击。失败显示仍由现有进度组件处理。
- 参考仓库当前 [ImageMojitoFragment.kt](https://github.com/XiaoMengXinX/c001apk_next/blob/main/mojito/src/main/java/net/mikaelzero/mojito/ui/ImageMojitoFragment.kt) 的失败分支有相同父层状态行为；本地根据真机证据补上失败后的触摸放行。

### 真机验证

- 诊断 Debug 包在 OPPO PMX110 / Android 17 打开帖子图片后，日志确认失败层曾关闭预览；禁用失败层点击后，触摸进入 `MojitoView` 和 Sketch 图片视图。
- 双指外扩时缩放值从约 `2.39` 增至 `3.24`；反向捏合时降至约 `2.75`，说明双指放大和缩小链路已生效。
- 清除诊断日志与临时注入测试源码后，最终 `:app:assembleDebug` 成功，且干净 Debug 包已安装到真机。双击、单指拖动关闭、横向切换和单击退出尚未验收。

## 主导航液态玻璃改造至 Android 16

### 修改

- 主导航底栏和搜索圆钮改为 KSU/Miuix 风格效果链：饱和度 1.5、4dp 背景轻模糊、24dp 圆角边缘折射；选中胶囊增加低对比度纵向高光渐变，原有选中动画和 Material 点击/无障碍语义保留。
- 效果写入现有 XML `LiquidGlassFrameLayout` 的 backdrop 层；RuntimeShader 初始化或执行失败时回退为基础模糊，不引入 Compose 或额外运行时依赖。
- `minSdk` 提升至 33，`compileSdk`/`targetSdk` 提升至 36，AGP 升至支持 API 36 的 8.9.1，Gradle Wrapper 维持 8.14.5。
- README、项目上下文、架构、决策、待办和开发指南同步更新。

### 决策与风险

- Miuix blur 是 Compose backdrop API，当前主页面以 XML/ViewPager2 构建，因此沿用现有 sibling backdrop 采样并实现等价 View 渲染链，避免把整个 UI 栈迁移到 Compose。
- 主导航原有 WindowInsets margin 和 `OnBackPressedDispatcher` 保留；Android 16 全应用行为（特别是大屏自适应、系统栏、字体和调度变化）仍须后续验收。

### 验证

- 使用 Android Studio JDK 21、Gradle Wrapper 8.14.5 执行 `:app:assembleDebug`，最终 Debug APK 构建成功；编译期间还修正了 Kotlin 2.2 nullable 平台类型、Hilt metadata/KAPT 兼容，以及 `utilcode` 传递引入的重复旧 Parcelize runtime。
- `git diff --check` 通过。未运行自动化测试或设备视觉检查；UI-GLASS-002 保持待验收，不能据此宣称 AGSL 已在设备上生效或性能达标。

## KernelSU 底栏源码对照与视觉修正

### 发现

- 首版已在 OPPO PMX110 / Android 17 真机安装和导航 smoke test，但用户反馈玻璃效果仍明显逊于 KernelSU。
- 对照 KernelSU `FloatingBottomBar.kt` 和 `BottomBarMiuix.kt` 后确认，上游把外层玻璃和选中胶囊分层绘制；外层填充 0.4、4dp blur、24dp lens、至少 40dp 采样留白及低强度 bloom 高光；选中胶囊独立用 10dp/14dp lens 与明暗轻填色。首版只有外层效果，选中项仍是渐变，通用高对比描边也偏重。

### 修改

- 保留 XML/ViewBinding 和 Material 导航控件，新增独立 LiquidGlassFrameLayout 胶囊并由 AnimatedBottomNavigationView 按当前动画边界驱动。
- 首次设备截图发现选中胶囊在静止时仍持续折射底下文字。复核 KernelSU `DampedDragAnimation` 后确认 pressProgress 初始为 0、交互时到 1、落位后回到 0；据此改为仅在胶囊移动时启用 lens 和高光，静止时保留 0.1 明暗填色。
- 主导航表面填充调整为 0.4、采样留白至少 40dp、取消双层硬描边并保留低透明度高光；搜索玻璃沿用同一轻量边缘样式，搜索入口保留。
- 底栏/搜索组合左右外边距调整为 28dp，外层增加 4dp elevation；保持 API 33 最低版本与 Android 16 target 配置。
- 仅移植上游公开的层级关系和视觉参数，没有复制 KernelSU GPL 源码。
