## 2026-08-12 API 身份修复、同类仓库对照与浏览复验

### 修改

- 参考 [Coolapk-API-Collect](https://github.com/Coolapk-UWP/Coolapk-API-Collect) 的 HTTP 首部、主页 V8 和动态详情资料，将首页与动态详情切换到 API1。
- 将 `X-App-Token` 的时间戳从 Float 秒改为整数 Unix 秒，并接通已有的自定义 Token 设置：仅在开关开启且值非空时覆盖自动生成 Token。
- 停止在启动时把 `/v6/apk/detail` 返回的线上应用版本写入第三方客户端的请求 Header，保持默认 `13.4.1/2312121` 请求身份稳定。
- 只读克隆 [HDYOU/c001apk](https://github.com/HDYOU/c001apk) 快照进行对照：其已注释掉远端版本写回逻辑，但仍保留 Float Token 和 API2 首页/详情路由，因此未直接复制。

### 验证

- `:app:testDebugUnitTest`：6 个用例，0 failures、0 errors、0 skipped。
- `:app:assembleDebug`：通过；正常 Debug 包的 `ENABLE_HTTP_BODY_LOGGING=false`。
- Android 16 `emulator-5554` 清空测试包状态后，应用详情、首页 V8、动态详情 `id=73186553` 和动态评论均返回 `200 OK`。
- UIAutomator 确认首页头条显示真实动态正文；点击后 `FeedActivity` 显示“动态”和完整动态正文，未再出现“加载失败”。

### 结论

问题不是单纯缺少 `X-App-Token`：请求原本已经发送该 Header，但 Float 时间戳、错误的 API2 路由以及自动写入线上应用版本共同造成拒绝。当前匿名浏览最小链路已在模拟器通过；登录、发布、图片、真实设备和 Release 仍未完成验收。

## 2026-08-12 Android 16 16 KB 页面大小兼容性修复

### 用户目标

修复打开应用时 Android 16 16 KB 模拟器提示应用不兼容的问题。

### 复现与定位

- 设备为 `emulator-5554` / `Pixel_10`，系统页大小 `16384`。
- 旧包冷启动时出现 `PageSizeMismatchDialog`，提示 `lib/arm64-v8a/libpl_droidsonroids_gif.so` 的 `RELRO segment not aligned`。
- ELF 检查确认问题集中在旧 GIF AAR 内置的 `libpl_droidsonroids_gif.so`，不是普通 APK zip 对齐问题。

### 修改

- `gradle/libs.versions.toml`：AGP 升至 8.5.1，GIF 依赖切换到 `pl.droidsonroids.gif:android-gif-drawable:1.2.32`。
- `SketchImageViewLoader`：移除旧 Sketch GIF 的 BuildConfig 依赖和 protected bitmap hook，改用新库公开的当前帧 API；普通图片 bitmap pool 路径未改。
- `app/build.gradle.kts`：为 instrumentation 回归测试增加 test-only GIF 依赖。
- 新增 `GifNativeCompatibilityTest`，用最小 GIF 实际创建并释放 `GifDrawable`。
- 同步更新 README、context、development、decisions、todo 和 changelog。

### 验证

- `:app:assembleDebug`、`:app:testDebugUnitTest`、`:app:bundleDebug`：通过。
- Debug APK：`zipalign -P 16` 和 native ELF 对齐检查通过。
- Debug AAB：`bundletool dump config` 显示 `PAGE_ALIGNMENT_16K`；Bundle 生成的 device APK 对齐通过。
- `:app:connectedDebugAndroidTest`：Pixel_10 上 2 个测试通过。
- APK 与 Bundle 生成的 APK 均在 16 KB 模拟器冷启动成功，无 `PageSizeMismatchDialog`、`RELRO` 或 native 崩溃日志，`pageSizeCompat=0`。

### 边界

Release 签名、真实设备、完整人工图片业务路径和 GIF bitmap pool 的性能变化仍未专项验收；没有通过兼容性开关压制提示。
