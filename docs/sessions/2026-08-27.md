# 2026-08-27 GitHub 更新真机续测与浏览器下载路径

## 用户目标

继续验证 GitHub Releases 客户端更新流程。用户反馈国内 GitHub 访问不稳定，要求检测到更新后交给系统浏览器下载；同时确认 Debug 包与正式包的覆盖安装边界。

## 真机证据

- 设备：OPPO `PGEM10`，Android API 36，serial `a60fe293`。
- 通过“我的 → 设置 → 其他 → 检查本客户端更新”进入 `ClientUpdateActivity`。
- latest API 请求成功，页面识别 `c001apk v1.1.0`，当前安装 Debug 包为 `versionName=fd943fc`、`versionCode=465`。
- 旧版应用内下载得到 `c001apk_v1.1.0.463.apk`；设备端 SHA-256 为 `9b7af318a0f6ecb3a18206271eeb877d5d25d02481988e4946f16e30c7d1dfb6`，与已发布 Release 记录一致。
- 点击系统安装器后显示“下载包版本不高于当前版本”。原因是下载包 `versionCode=463` 小于旧 Debug 包 `versionCode=465`；这是 Android 正确的降级保护，不能通过放宽版本校验修复。该旧版安装链路仅作为问题诊断证据，当前实现已删除。

## 实现调整

- 更新页提供“浏览器下载 Release（推荐）”，固定打开 `https://github.com/godmiracle/Coolapk/releases/latest`；初始、检查成功和检查失败状态均可使用。
- 删除应用内 APK 下载、SHA-256 流式缓存、FileProvider 更新路径、未知来源授权引导和系统安装器 Intent；GitHub API 只返回并校验 Release 元数据。
- GitHub OkHttp client 固定使用 HTTP/1.1 并关闭重定向，避免应用 API 请求进入未知 Host。
- Debug 构建增加 `applicationIdSuffix = ".debug"`，Debug 包为 `com.godmiracle.coolapk.debug`；正式包仍为 `com.godmiracle.coolapk`。两者使用不同签名/包名，可并存安装。
